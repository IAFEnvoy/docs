Bot 模块可推送新增 Issue 和[自动预处理报告](./issue-preprocessing.md)。当前提供基于官方 BotGo 的 QQ 适配器，通过 **WebSocket 长连接接收事件**，默认关闭。

## 启用 QQ Bot

1. 在 QQ 开放平台创建机器人，取得 AppID 和 AppSecret，启用群聊能力，并配置服务器出口 IP 白名单、所需接口权限和测试成员。
2. 编辑 `config/bots.yml`，启用总开关和 `providers.qq.enabled`，填写凭据；完整示例见 [bots.yml](../configuration/bots-yml.md)。首次启动会从模板生成默认关闭的配置。
3. 重启服务。Bot 配置不参与管理菜单的配置热重载。
4. 查看 `[QQBot]` 日志：先获取凭证，再建立连接；收到 `READY` 后会记录 WebSocket 接入成功。

服务需要能够访问 QQ 的 HTTPS 和 WSS 接口。事件连接自动订阅群聊 @机器人消息 `GROUP_AT_MESSAGE_CREATE`；无需配置公网回调 URL 或开放入站回调端口。若此前配置过 Webhook，请停用旧配置，原 `/api/bot/qq/webhook` 路由已移除。

## 网站生成一次性码，在群里绑定

1. 登录网站，打开 **Agent → 设置 → QQ 群通知绑定**。设置标签位于 **MCP 服务器** 右侧。
2. 点击 **生成绑定码**。
3. 在需要接收通知的群中 **@机器人**，发送 `/bind 绑定码`。
4. 机器人回复绑定结果，网站每 5 秒刷新绑定列表；回复失败时也可在网站确认是否已经绑定。

绑定码有效期为 **10 分钟**，仅限一次使用；重新生成会使该账号原先的同类绑定码失效。只将码发送到目标群。服务端从已鉴权的 QQ 事件读取 `group_openid`，不需要手动获取 OpenID，也不能用 QQ 群号替代它。

生成、查看和解绑都需要登录；账号只能查看、解绑自己的绑定，其他账号不能接管已经绑定的群。绑定跨重启保留，新绑定只接收之后的通知。网站解绑会移除该群待发送的通知，已在发送中的消息可能仍然到达。配置文件中的固定 `targets` 需通过修改配置并重启移除。

### 指令回复

| 群内 @消息 | 回复 |
| --- | --- |
| `/bind 有效绑定码` | 绑定成功说明 |
| `/bind` 或格式错误 | 绑定用法 |
| 失效、已用或过期的码 | 提示在网站重新生成 |
| 已绑定的群 | 提示查看已有绑定 |
| 其他消息或仅 @机器人 | 功能说明和绑定用法 |

这些反馈使用消息 API 的**被动回复**，携带原始 `msg_id` 和 `msg_seq: 1`，不需要主动消息授权。发送失败最多尝试 3 次，同一回复沿用原序号；短时间内重复收到事件不会重复处理绑定。

## 开启主动推送

绑定完成后，**群主**还需要使用新版手机 QQ，在群成员列表中选择机器人，进入它的**群消息设置**，允许主动推送。单聊则由用户在机器人资料页开启主动消息。平台权限和配额依然适用。

绑定与主动消息授权是两个步骤。能收到 `/bind` 的回复，不代表已允许新增 Issue 或报告推送。QQ 错误码 `40034105` 通常表示未允许主动消息。

## 通知范围与恢复

| 通知 | 触发规则 |
| --- | --- |
| 新增 Issue | GitHub TTL 或手动清缓存后的成功刷新，只发送新增且仍为 Open、项目未归档的 Issue；每次重启后各仓库首次拉取仅校准基线 |
| 预处理报告 | 预处理成功后发送最终报告正文，长报告分段发送 |

新增 Issue 通知独立于预处理开关，仍需要启用 GitHub 数据源并提供仓库所有者的 Token。历史 Issue、PR、旧 Issue 编辑和重新打开不会产生新增通知。报告只包含最终正文，不包含附件原文、工具输出和推理；看板链接仍需登录，不自动创建公开分享链接。

`data/bot-notifications.json` 保存绑定、绑定码哈希、仓库基线、待发送通知和各目标的分段进度。失败消息按 10–320 秒退避重试，重启后续发未完成分段；移除目标或关闭通知类型会丢弃相应待发内容，不转发给新目标。

发送采用至少一次语义：平台已经接受消息而本地尚未保存进度时崩溃，可能重复发送。网络和平台配额也可能造成延迟。

## 登录与连接日志

| 日志 | 含义与排查 |
| --- | --- |
| `[QQBot] 登录成功` / `登录失败` | 凭证获取结果；失败时检查 AppID、AppSecret 和网络 |
| 刷新登录凭证成功或失败 | 凭证过期后的刷新结果；缓存命中不重复记录成功 |
| `WebSocket 接入成功 READY` | 已完成事件连接鉴权 |
| `WebSocket 连接中断` | 将退避重连；心跳确认超时也会触发重连 |
| `会话恢复成功 RESUMED` | 已通过会话 ID 和序号恢复连接，QQ 会先补发遗漏事件 |
| `WebSocket 接入已停止` | 检查错误码、分片、事件权限、机器人状态与环境；不可重试错误会停止接入 |
| `[Bot] QQ 群消息回复失败` | 检查 QQ 错误码与 traceID，区分绑定是否成功和回复是否送达 |

凭证日志不输出 AppSecret 或 Token；连接日志不记录消息正文和绑定指令。连接按 QQ 下发周期发送心跳，消息处理与心跳独立，回复阻塞不会阻塞心跳。

## 接口与扩展

`/api/admin/bot-bindings` 的 GET、POST、DELETE 均需要网站登录，分别用于查看当前账号的绑定、生成一次性码和解绑。QQ 的连接鉴权使用 Bot 凭证。

通用 `bot/` 模块负责绑定码、事件、存储和通知队列；`bot/qqbot/` 负责 QQ 鉴权、WebSocket 事件与消息发送。新增平台时实现 `bot.Sender` 的 `Validate` / `Send`，在 `bot.go` 注册适配器与配置；平台自己的事件接收逻辑放在独立适配器内。

参考：[QQ WebSocket 接入](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/event-emit/websocket.html)、[群聊 @消息事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html)、[QQ Bot 常见问题](https://bot.q.qq.com/wiki/bot_FAQ/)。
