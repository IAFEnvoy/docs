## 选择并完成开局

1. 在左侧窄栏选择预设，或直接在右侧选择选项。单选组会替换此前选择；可重复项使用减号和加号调整数量。
2. 查看底部资源余额和失败原因。鼠标悬停可查看选项说明、资源贡献、奖励和预设内容。
3. 调整数量，直到全部规则通过。切换职业可能改变价格和数量上限，原有超限数量会保留，需要自行修正。
4. 点击确认。只有服务端接受提交后，最终资源和奖励才会生效。

预设整体替换当前选择；它不会额外发放点数或奖励。手动调整后显示为自定义，选择集再次精确匹配时会重新标识预设。重置清空选择，保留本次会话的资源基准和输入。

左右两栏分别滚动，鼠标滚轮只作用于指针所在区域。窄窗口通过预设按钮打开左栏列表。隐藏或不可用但已选中的项会出现在需要处理的选择中，仍可取消。

## 关闭与伤害保护

默认必须确认开局后才能关闭；即使点数已经符合要求，尚未确认时也不能用 Esc、保存并关闭或其他游戏内界面替换它。

方案配置 `ui.allow_close_before_complete: true` 后，可以保存草稿并关闭。关闭需要等待服务端回执，重新打开会恢复草稿。

界面打开期间由服务端忽略伤害，包括虚空伤害。确认、允许的关闭、管理员解锁或断线会解除这次保护。界面不暂停游戏。

## 快捷键

| 按键 | 操作 |
| --- | --- |
| `1`～`9` | 应用对应位置的预设 |
| 左右方向键 | 移动选项焦点 |
| 上下方向键 | 按卡片行移动焦点 |
| Enter / Space | 切换焦点选项 |
| Ctrl + Enter | 确认开局 |
| Page Up / Page Down | 滚动选项区 |

## 命令

| 命令 | 使用者 | 作用 |
| --- | --- | --- |
| `/starting_point_buy open [plan]` | 玩家本人 | 打开或继续方案；无当前会话且省略 ID 时寻找自动方案 |
| `/starting_point_buy status` | 玩家本人 | 查看当前方案、状态、revision、任务和完成记录数量 |
| `/starting_point_buy refresh` | 玩家本人 | 刷新尚未提交的会话 |
| `/starting_point_buy unlock <player> [plan]` | 游戏管理员 | 清理目标玩家的指定方案记录；省略方案时清理全部开局记录 |
| `/starting_point_buy recover <player>` | 游戏管理员 | 释放处于 `NEEDS_REVIEW` 的会话，继续处理剩余任务 |

默认每位玩家在每个世界中，每个方案只能完成一次。重复提交不会再次发放奖励。

## 刷新草稿 {#refresh}

当真实资源已被其他系统修改，或数据包定义发生变化时，草稿会要求刷新。此时底部的“重置”按钮会变成“刷新草稿”，点击即可在当前界面恢复编辑，无需关闭。刷新会重新读取当前真实资源，重新捕获 `inputs`，并保留仍可识别的选项。强制完成与打开期间的伤害保护继续生效，也可以使用 `/starting_point_buy refresh` 刷新尚未提交的会话。

刷新不会重新计算 `initial`；它使用当前真实资源作为新基准。已提交或已完成的方案不能刷新。重置则只清空数量，不改变基准，也不重抽已捕获输入。

## 管理员解锁和任务恢复

`unlock` 会清理匹配的会话、完成记录和该模组维护的能力授予记录。如果当前匹配会话已提交，还会将其 `commit: replace` 资源恢复到该会话基准。**已执行动作发放的物品或世界变化不会撤销。**更早方案的资源没有当前会话基准可供回滚。

任务失败、执行前落盘失败或服务器在动作执行附近中断时，可能进入 `NEEDS_REVIEW`。先查看日志、确认玩家已收到的奖励，再使用 `recover`。失败和不确定的任务不会自动重放；该命令让尚未执行的任务继续处理，不代表补发失败奖励。
