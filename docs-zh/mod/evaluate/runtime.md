## 查看价值

客户端和服务端都安装 Evaluate 与 Saturn 后，按 **F3+H** 开启原版高级物品提示，再悬停物品。

提示显示的是**单件价值**，不乘整组物品数量。当前格式保留两位小数，API 中的原始 `double` 不受影响，因此很小的正价值可能显示为 `0.00`。

未知和免费物品没有价值行。首次悬停会发送查询，等待服务端响应时可能暂时没有显示。关闭高级物品提示后隐藏价值行。

## 缓存

| 位置 | 缓存内容 | 生命周期 |
| --- | --- | --- |
| 服务端 | 计算图结果、固定规则与最终覆盖的不可变快照 | 资源重载或外部失效后替换。 |
| 客户端 | 按物品和组件补丁区分的查询结果，包括未知结果 | 收到重载通知、登录和退出时清空。 |

普通查询复用服务端快照。显式组件规则仍匹配实际物品栈，不会按整个物品 ID 缓存成同一个结果。

客户端最多保存 **1024** 项 LRU 结果，以及 **64** 个待响应查询。反复悬停会合并同一项的等待请求；失效前发出的请求即使延迟返回，也不会重新写入旧数值。

## 修改后如何重载

| 修改内容 | 操作 | 结果 |
| --- | --- | --- |
| Evaluate 数据包定义或配方 | `/reload` | 重读定义、重建计算图并使客户端价值缓存失效。 |
| KubeJS 服务端脚本或生成定义 | `/reload` | 随资源集一起重载脚本贡献和回调。 |
| 磁盘中的 FTB 任务文件 | `/ftbquests reload quests` | 加载任务书，Evaluate 在下一次服务端 tick 重算。 |
| FTB 编辑器中的变更 | 应用编辑 | FTB 缓存清理事件安排下一次服务端 tick 重算。 |

数据包成功重载后，Evaluate 等配方、标签和默认组件就绪，再重新计算并替换快照。已删除的定义和关系不会保留，客户端提示随后按需重新查询。

`/reload` 使用**当前内存中**的 FTB 任务书重算关系，不会重读 FTB 的磁盘文件。可采纳的任务类型见 [FTB Quests](./ftb-quests.md)。

Java 调用方若保留了旧的 `ItemValues.all()` 返回值，需要在重载后重新获取。旧的不可变 Map 不会原地更新，计算器和覆盖注册表的快照也应重新获取。

## 为什么没有物品价值？

可按以下顺序排查：

1. 确认文件位于 `evaluate/evaluator/` 或 `evaluate/value_override/`，目录为单数，字段合法。
2. 检查匹配优先级，以及基础值或最终覆盖是否将该物品设为 `0`。
3. 确认所需输入均有已知价值，且配方实现受支持。
4. 检查查询是否使用了尚未收集到推导图中的组件变体。
5. FTB 任务检查消耗开关、可重复设置、目标类型和奖励限制。
6. 查看服务端日志中的无效定义、缺失 JS 回调、跳过的任务和循环组超限提示。

可以用[固定基础值](./datapack.md)提供缺失的起点，或用[脚本](./kubejs.md)、[Java 计算器](./java.md)接入未支持的计算来源。
