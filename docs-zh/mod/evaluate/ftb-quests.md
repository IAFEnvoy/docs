可选安装 **FTB Quests `26.1.2.8+`** 及其依赖。Evaluate 的内置 `evaluate:ftb_quests` 实例读取服务端已加载的任务书。未安装 FTB Quests 时不提交关系，其他计算器照常运行。

## 配置

替换内置文件即可修改参数：

```json title="data/evaluate/evaluate/evaluator/ftb_quests.json"
{
  "type": "evaluate:ftb_quests",
  "repeatable_only": true,
  "extra_value": 0.0
}
```

| 字段 | 类型 | 必填 | 默认值 | 含义 |
| --- | --- | --- | --- | --- |
| `type` | 资源 ID | 是 | — | `evaluate:ftb_quests`。 |
| `repeatable_only` | 布尔值 | 否 | `true` | 要求实际生效的可重复设置为真，包括章节默认值。 |
| `extra_value` | 有限非负 `double` | 否 | `0` | 每次兑换的附加价值，按奖励数量分摊。 |
| `comment` | 字符串 | 否 | — | 可选说明。 |

将 `repeatable_only` 设为 `false`，也会采纳一次性消耗任务。此类奖励只能获取有限次数，推导候选不代表可持续获取。

## 可采纳的兑换

整条任务需要满足：

- 所有必需目标均为 FTB 原生物品任务，且实际消耗物品；遵循章节和全局继承的消耗设置。
- 可选目标不计入消耗，排除后至少还剩一个必需输入。
- 所有奖励均为 FTB 原生固定物品奖励，没有 `random_bonus` 或 `only_one` 条件行为。
- 物品栈有效，输入任务没有使用自定义物品过滤器或仅限合成限制。

收集任务、其他必需目标类型、随机或选择奖励、经验、货币、命令、自定义奖励，以及缺失模组物品，都会使整条任务跳过。即使混合奖励中包含固定物品，也不会只抽取这一部分。

## 计算方式

```text
奖励单件候选价值 =
    (消耗数量 × 输入单件价值之和 + extra_value) / 奖励数量
```

两枚单件价值 `256` 的铁锭，固定奖励四枚代币，附加价值为 `2` 时，每枚代币候选价值为 `(2 × 256 + 2) / 4 = 128.5`。

| 细节 | 行为 |
| --- | --- |
| 重复输入或奖励条目 | 物品及组件相同的条目分别合并数量。 |
| 奖励数量 | 使用 FTB 独立的 `count`，不再乘配置物品栈内的数量。 |
| 多种固定奖励 | 每种产物各自承担完整输入成本，不分摊或抵扣其他奖励。 |
| 任务忽略组件 | 使用默认物品栈作为可接受输入。 |
| 严格或模糊组件匹配 | 使用任务配置中可接受的组件栈作为输入代表。 |
| 输入未知 | 阻止该奖励候选的推导。 |
| 数量过大 | 单项任务超过 `Integer.MAX_VALUE` 或合并数量溢出时，跳过并警告。 |

只建立支付物品到奖励的有向关系，不根据奖励反推支付物品。任务结果可以在[统一计算图](./calculation.md)中继续用于配方或其他任务；固定基础值保持优先，最终覆盖不参与传播。

不读取玩家进度，不给解锁依赖、冷却时间或队伍人数附加成本和奖励倍数。每条关系使用配置列出的一份固定奖励。

## 加载与更新

FTB Quests 26 使用 `config/ftbquests/quests/` 下的 JSON5 文件，在 `ServerStartedEvent` 中加载任务书。Evaluate 的首次计算安排在它之后。

修改磁盘文件后执行 `/ftbquests reload quests`。FTB 编辑器变更和任务重载会触发缓存清理事件，其中部分修改在事件之后才完成，因此 Evaluate 等到下一次服务端 tick 再重建图并通知客户端清理价值缓存。删除的兑换关系会从新快照中清除。

普通 `/reload` 会重读 Evaluate 参数，并使用内存中的任务书重新计算，不会重读 FTB 文件。具体区别见[运行与重载](./runtime.md)。
