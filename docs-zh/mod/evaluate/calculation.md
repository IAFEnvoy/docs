所有计算器向同一张图提交关系。[任务兑换](./ftb-quests.md)、配方和[脚本计算器](./kubejs.md)可以使用彼此的结果，不受注册顺序限制。

固定基础值优先于推导候选值。没有固定基础值的物品，在所有有效获取方式中取最低成本。[最终覆盖](./datapack.md#final-overrides)只在求解结束后应用。

## 配方计算器 {#recipe-evaluators}

`data/evaluate/evaluate/evaluator/recipes/` 下有七个内置实例：

| 文件 | 配方类型 |
| --- | --- |
| `crafting.json` | `minecraft:crafting` |
| `smelting.json` | `minecraft:smelting` |
| `blasting.json` | `minecraft:blasting` |
| `smoking.json` | `minecraft:smoking` |
| `campfire_cooking.json` | `minecraft:campfire_cooking` |
| `stonecutting.json` | `minecraft:stonecutting` |
| `smithing.json` | `minecraft:smithing` |

默认附加价值为 `0`。要给每次熔炼增加成本，替换内置文件：

```json title="data/evaluate/evaluate/evaluator/recipes/smelting.json"
{
  "type": "evaluate:recipe",
  "recipe_type": "minecraft:smelting",
  "extra_value": 2.5
}
```

| 字段 | 类型 | 必填 | 默认值 | 含义 |
| --- | --- | --- | --- | --- |
| `type` | 资源 ID | 是 | — | `evaluate:recipe`。 |
| `recipe_type` | 配方类型注册表 ID | 是 | — | 要扫描的类型；自定义类型中的配方实现仍需受支持。 |
| `extra_value` | 有限非负 `double` | 否 | `0` | 每次执行的附加价值，按产出数量分摊。 |
| `comment` | 字符串 | 否 | — | 可选说明。 |

使用其他资源 ID 新增实例时，两个实例都会保留。如果它们扫描相同配方但附加价值不同，关系会同时参与比较，较低成本者生效。修改内置参数时应覆盖同一路径。

## 成本计算

```text
输出单件价值 =
    (输入总价值 - 返还物价值 + extra_value) / 产出数量
```

例如输入总价值为 `12.5`，产出两件物品，附加价值为 `2.5`，则每件价值为 `(12.5 + 2.5) / 2 = 7.5`。

输入数量会计入成本。可替代材料提供不同候选成本，合成返还物会先从对应选项中抵扣，再选择最低成本。所需输入或返还物未知时，该候选无法计算，不会被当作免费物品。

| 输入状态 | 影响 |
| --- | --- |
| 固定正价值 | 使用配置值，更便宜的配方不能降低它。 |
| 推导正价值 | 可以继续用于其他配方和兑换。 |
| 已知零价值 | 作为免费输入参与计算，但不公开正价值。 |
| 未知价值 | 阻止依赖该物品的关系推导。 |

价值保留小数：铁锭为 `256` 时，铁粒为 `256.0 / 9`，重新打包不会因逐步取整损失价值。配置、存储和查询结果使用 `double`。非有限结果，以及正值超出可表示范围而下溢的结果，不会作为免费物品公开。

## 自动支持的配方

Evaluate 自动映射输入数量和静态输出可确定的普通配方：

- 有序与无序合成。
- 熔炼、高炉、烟熏和营火烹饪。
- 切石与锻造转换。
- Minecraft 26.1 的 `crafting_transmute`。

动态特殊配方、自定义 Ingredient 实现、酿造、掉落和交易暂不自动推导。例如装有液体的桶，在没有受支持的关系时，需要显式定义或其他计算器提供价值。

## 循环保护 {#cycles}

正常的打包与拆包配方可以稳定求解。没有已知起点的循环不会凭空产生价值。

同时存在 `1 A → 2 B` 和 `1 B → 1 A` 这样的兑换时，推导成本会反复降低。Evaluate 将相互依赖的节点划分为强连通分量，先计算外部依赖，组内稳定后才发布结果。无关配方不会增加该循环的计算额度。

| 保护项 | 当前行为 |
| --- | --- |
| 每个节点的成功更新次数 | `max(64, min(256, 组内节点数 × 2))` |
| 每个循环组的计算量 | 最多 `1,000,000` 次配方／输入求值步骤 |
| 浮点下限 | 临时使用 DECIMAL128，避免 `double` 下溢被误判为收敛。 |
| 舍入误差 | 循环组内使用约 `1.78e-15` 的相对容差。 |
| 深层依赖 | 迭代遍历，不因递归导致 Java 调用栈增长。 |

超过任一计算限制时，整组推导结果会被剔除并记录日志，临时异常值不会传入下游。下游物品仍能使用独立的正常配方获得价值。固定基础值保持优先，对外结果和存储仍为 `double`。

保护策略偏保守：异常缓慢但能够收敛的组也可能被剔除。此时可以为合适的物品设置固定基础值，切断该推导依赖循环。
